# Полный собственный мод на Rust / WebAssembly

Собственные функции перенесены в `rust-mod/src/generated.rs`; поддержка
вызовов WebAssembly находится в `rust-mod/src/lib.rs`. В исходнике 406 функций
и обработчиков, включая баллистическую модель, ILM/BBY-адаптер, меню, настройки,
отображение, автоматизацию, вход, таймеры, bootstrap и загрузчик.

Нативная игра, сторонняя библиотека dat.GUI и браузерные API остаются
JavaScript. `bridge.js` предоставляет общие операции с динамическими
JavaScript-значениями, объектами и callback-функциями. Управляющая логика
собственного мода компилируется в Wasm из Rust. Эта версия использует `JsValue`,
а не строгую числовую модель для каждого поля игры; из этого переноса нельзя
делать вывод об ускорении или уменьшении расхода памяти.

Файл `generated.rs` получен при исходном переносе с помощью
`tools/rust_transpile.cjs`, затем отформатирован rustfmt. Это обычные Rust-функции
с условиями, циклами, возвратами и обработкой исключений, а не сохранённый AST
для интерпретации JavaScript. Имена исходных функций приведены в комментариях,
соответствие всех функций — в `function-manifest.json`.

## Установка инструментов

Нужны Rust stable, Node.js и wasm-bindgen CLI той же версии, что в Cargo.lock:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.105 --locked
npm ci --ignore-scripts
```

## Сборка

Из корня проекта или автономного исходного архива:

```sh
node tools/build_rust.cjs
node tools/build_rust_client.cjs
node tools/rust_source_smoke.cjs
```

Сборщик читает `.rs`, Cargo.lock, `bridge.js` и закреплённую основу
`rust-mod/native-base/`. TypeScript для этих команд не требуется. Основа содержит
сжатые префикс и суффикс уже проверенного клиента игры; прежние исполняемые
функции мода из неё удалены. Их место занимает Rust/Wasm и общий мост.
Хеши префикса/суффикса проверяются до сборки.

При адаптации полей к закреплённому игровому JS сборщик создаёт временный
Rust-файл с текущими именами нативных полей. Основные `.rs` при этом не меняются.
Каталоги `target/` и `.native-build/` — локальные кеши компиляции.

Результат: `artifacts/rust-mod-2026-11-24/Devast-io-Rust-Resource-Override.json`.
Он содержит весь клиент и Wasm, дополнительных сетевых загрузок Wasm нет.
Импортировать в Resource Override, отключить прежнее правило игрового JS и
перезагрузить страницу.

## Изменения и обновления

Для Rust-варианта редактировать `.rs` и выполнять сборку выше. Команда
`tools/generate_rust.cjs` предназначена для повторения исходной миграции из
архивного JavaScript-варианта; она перезаписывает `generated.rs`, поэтому её
нельзя запускать поверх собственных Rust-изменений без сохранения.

В полном репозитории обычная команда `npm run build` и существующий GitHub
auto-update продолжают собирать прежний JavaScript-вариант. Rust-вариант пока
отдельный локальный выпуск. Для смены игровой основы сначала требуется
проверенный перенос нативного клиента, затем явное закрепление этой основы:

```sh
node tools/build_rust_client.cjs --pin-native
```

После этого обязательны повторные функциональные и браузерные проверки.
Сборка сама ничего не отправляет в GitHub.

## Проверки

В полном репозитории `npm run test:rust` запускает прежние сценарии с настоящим
WebAssembly-модулем вместо JavaScript-реализации. Проверки модели, настроек,
сохранений, меню, таймеров, транспорта и очистки работают через Rust.
Самостоятельная проверка загрузчика также выполняет Rust-модуль.
Нативные браузерные fixtures проверяют весь клиент в Chromium и Firefox;
их результаты относятся к конкретному SHA в `verification.json` выпуска.

Живая серверная сессия, отсутствие киков и точность на реальном сервере этими
проверками не устанавливаются. Перенос на Rust сам по себе не меняет физику
игры.
