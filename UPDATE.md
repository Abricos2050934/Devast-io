# Перенос на текущий клиент

Целевой репозиторий: `Abricos2050934/Devast-io`.

## Основа и сборка

Источник получен 2026-11-01 из свежего HTML `https://devast.io/`:
`https://devast.io/js/GqIvLJdVfXmKlyX.js`, HTTP 200, 6 923 876 байт.
SHA-256:
`b2752241a0a1491b5bd48146c7c3c4937f490928df5cab058ba80d32a413acc1`.
Оригинал сохранён без изменения в `baselines/current.js.gz`.

Предоставленный мод был собран на другой обфускации. Его точная копия
сохранена в `recovery/game.modded.ilm.js.gz` (7 080 929 байт, SHA-256
`9c4448cfd9029816dd0def23cb5df3cf242c0569812dcbc14fd70b35c8b03a70`).
История Git, прежние ZIP/bundle, инструменты и профили не восстановлены:
они отсутствовали во вложениях.

`mod/responsive.js` сохраняет канонические для этого исходника имена.
`tools/translate_payload.cjs` переводит только собственные вставки, включая
строковые имена обработчиков. Оригинальный клиент глобально не переименовывается.
`vendor/dat.gui.recovered.js` извлечён из того же вложения.

`patches/recovered-bindings.json` содержит соответствия и основания сопоставления:
экспорты сетевого объекта/мира/коллекций/отрисовки, конструкторы сущностей,
инициализация локального игрока, обработчик метаданных, поля клана и шкал.
Семантические признаки включают индексы полей пакетов, настоящий ID игрока,
нативный путь получения/удаления объектов и таблицу изображений karma.
Пять содержащих старые вставки функций дополнительно сопоставлены по AST-токенам;
совпадение структуры существенно выше ближайших альтернатив. Это не заменяет
проверку всех функций в живой игре.

`patches/recovered-current.json` фиксирует точный SHA-256 и шесть уникальных
точек: камера, получение позиций, удаление объектов, масштаб, видимость мин,
прозрачность построек. Два штатных обработчика угла оборачиваются через
экспортированный сетевой интерфейс; при выключении наведения работает оригинал,
а dispose восстанавливает исходные функции. Оригинальные динамически создаваемые
функции сетевого кода не распаковывались запуском клиента в Node.

Профили `recovered-*.json` имеют собственную документированную схемой
`recovered-port-v1` структуру для этого переноса; это не якобы восстановленные
форматы отсутствующего старого конвейера.

```sh
cd /workspace/Devast-io
npm ci --ignore-scripts
npm run build
npm test
node --check dist/game.modded.js
```

Неизвестный SHA-256, неоднозначная точка вставки или ошибка разбора останавливают
сборку до перезаписи JS и статуса. Автоматического сопоставления неизвестной
версии нет. Изменение ожидаемого хеша не является переносом.

## Результаты проверки

13 тестов: 3 Python и 10 Node. Дополнительно проходит AST-разбор и `node --check`.
Проверяются побайтовое восстановление вложения, перевод символов, отказ на
неизвестной основе и неоднозначной вставке с сохранением старых файлов,
сохранение настроек без полей аккаунта, клавиши при вводе текста, упреждение,
передача угла, ограничения подбора и освобождение ресурсов.

Chromium 154 запускался с HTTPS-прокси среды и доверием к его сертификату
через отдельную NSS-базу `/tmp/devast-browser-home/.pki/nssdb`.
Проверка TLS не отключалась. Использовался новый профиль без пользовательских
cookies, токенов и аккаунта.

Обычный клиент в одной из первых проверок вошёл в игру: состояние соединения 1,
ненулевой ID игрока. У перенесённой сборки меню открылось без ошибок диагностики
мода, но вход на Frankfurt/автоматически выбранные серверы завершался HTTP 503
при WebSocket-рукопожатии до получения ID. Это не подтверждённый кик после входа.
Повторные проверки обычного клиента тоже перестали успешно подключаться.
Затем HTTPS-запрос главной страницы через curl вернул 503 при успешном CONNECT 200:

```
upstream connect error or disconnect/reset before headers
remote address:envoy://cloudflare_https_tunnel/
```

Сеть среды unrestricted/enforced. Нельзя приписывать эту ошибку игровому античиту
или утверждать, что все серверы исправны/неисправны по результату такого запроса.

Финальная сборка отдельно проверена в Chromium с сохранённым HTML и локальной
подменой основного JS. Меню создано, обработчики и собственная диагностика мода
без ошибок. Проверка с искусственными данными на штатных структурах нового
клиента получила коллекцию сущностей, историю позиции и выполнила step без ошибок.
Из-за недоступных внешних ресурсов есть ошибки Widget/audio оригинальной страницы;

## Зависимости при сбое сети

Повторный `npm ci` в конце проверки также получил HTTP 503 от npm registry;
зеркало вернуло тот же статус. Целостность пакетов не отключалась, lockfile
не изменялся для обхода ошибки. Для текущей сборки и тестов `tools/parser.cjs`
использует доверенную копию Acorn 8.17.0 из установленного Node.js 24; при наличии
зависимости предпочтение имеет закреплённый Acorn 8.15.0. Об этом выводится
явное сообщение. Сборка и все 13 тестов повторены с этим резервным парсером.
Обычная переустановка зависимостей через registry до восстановления сети
не подтверждена. Браузерная проверка использовала установленный playwright-core
1.62.1; основной JS не зависит от Node или npm при запуске в браузере.

## Исправление повторного входа


Изменения в этой версии:

- Отдельно обработан отказ восстановления завершённой сессии (нативное состояние 256).
  После него разрешена одна обычная попытка входа с теми же сохранёнными данными.
- Сбрасывается только временное состояние сетевого подключения, влияющее на флаг
  восстановления. Cookies, token, tokenId, userId и настройки модификации не удаляются.
- Повторные нажатия Play до завершения начального запроса не создают параллельные
  подключения. Устаревший ответ предыдущей попытки не запускает новое соединение.
- Изменённый выбор сервера сохраняется; отложенный повтор старого подключения отменяется.
- Проверка повреждённого сохранённого userId исправлена: сравнение NaN === id никогда
  не срабатывало. Теперь применяется предусмотренное оригиналом конечное значение
  по умолчанию в пакете входа, без удаления или перезаписи хранилища аккаунта.
- Закрытие ещё не созданного WebSocket больше не вызывает обращение к undefined.
- Отказы по версии/доступу не запускают цикл сброса идентичности.

Проверки: 32 теста, синтаксис и AST. В Chromium вызван штатный обработчик отказа
восстановления на подготовленных нативных объектах: выполнена одна обычная попытка,
флаг пакета входа равен 0, cookies и данные аккаунта/настройки сохранились.
Отдельно проверен штатный пакет: при восстановлении флаг равен 1, при обычном входе 0;
остальные поля идентичности одинаковы. На испорченном сохранённом ID проверен fallback.

Это проверка клиентской логики, а не принятия входа реальным сервером. Последняя
попытка входа на Osaka 1 остановилась на WebSocket HTTP 503. Поэтому повторный вход
на живом сервере и отсутствие киков пока не подтверждены.

Установка: замените старый game.modded.js новым файлом в подмене основного скрипта,
затем перезагрузите страницу. Для применения исправления не требуется очищать cookies
или localStorage. Не выполняйте полный файл поверх уже работающего игрового клиента.
