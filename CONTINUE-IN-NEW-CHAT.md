# Devast-io — полная инструкция продолжения в новом чате

Снимок: 2 ноября 2026 года. Рабочий репозиторий:
https://github.com/Abricos2050934/Devast-io

Эта инструкция описывает уже выполненную работу. Новому чату сначала нужно
восстановить контекст и проверить файлы, затем выполнять новую задачу пользователя.
Не применять старые изменения повторно и не публиковать что-либо только ради
восстановления контекста. Указания пользователя в новом чате имеют приоритет.

## 1. Что передать новому чату

1. Прикрепить `Devast-io-Handoff.zip` целиком. Обычный `Devast-io-client.zip`
   содержит готовый клиент, но не заменяет полный архив проекта.
2. Вставить текст из `handoff/NEW-CHAT-PROMPT.txt`.
3. Если уже есть новая задача, дописать её после этого текста.

Для установки готового клиента есть `client/game.modded.js` и
`client/Devast-io-GitHub-Resource-Override.json`; в client/ также лежат обычные
клиентский ZIP и ZIP импорта. Это дополнительные удобные копии опубликованного
выпуска, не исходники для ручного редактирования.

В полном архиве лежат исходники, инструменты, тесты, workflows, готовый JS,
Resource Override, проверенная версия автообновления и материалы сравнения ILM.
Файлы внутри имеют относительные пути; распаковывать нужно с сохранением каталогов.

В архив не включены `.git`, `node_modules`, персональные cookies, токены,
учётные данные GitHub, переменные окружения и локальная `.npmrc`. Доступ к GitHub
в новой среде подключается обычным способом отдельно. Для разработки и проверки
кода игровые cookies и токены пользователя не нужны.

## 3. Первый запуск в новой среде

Прочитать применимые AGENTS.md/инструкции среды, проверить рабочую директорию и
`git status`, если она уже является checkout. Не выполнять reset/clean поверх
чужих или ещё не сохранённых изменений.

После распаковки перейти в каталог `Devast-io-Handoff`:

```sh
python3 handoff/verify_archive.py
```

Проверяются контрольные суммы всех файлов снимка. Эта команда ничего не
публикует и не подключается к игровому аккаунту.

Для полноценной разработки нужны Node.js 24, Python 3.12+, зависимости lockfile
и Chromium:

```sh
npm ci --ignore-scripts
npx playwright-core install --with-deps chromium
npm run build
npm test
```

Если Chromium установлен системно, валидатор автоматически использует
`/usr/bin/chromium`; другой путь задаётся через `CHROMIUM_PATH`.
`tools/parser.cjs` умеет использовать доверенный Acorn из Node, если npm-пакет
недоступен, но это не заменяет Playwright/Chromium для браузерной проверки.

В управляемой облачной среде прочитать актуальный runtime skill и проверить
статус среды/сетевую политику. Сохранить унаследованные HTTP_PROXY/HTTPS_PROXY,
CA и механизм учётных данных. Не переносить старые ID сред и не выводить
секреты в лог. HTTP 403/503 нужно фиксировать как фактическую ошибку доступа;
не отключать TLS и не объявлять непроверенный вход успешным.

Если нужен Git checkout, получить его в отдельную директорию:

```sh
git clone https://github.com/Abricos2050934/Devast-io.git
```

Архив не содержит Git-историю. При восстановлении через checkout сначала
сравнить версии и перенести только нужные изменения, сохранив новые файлы
пользователя. Для чтения публичного репозитория авторизация обычно не нужна;
для push нужны права в новой среде. Не помещать access token в файл инструкции.

## 5. Что уже сделано и нужно сохранить

### Аимбот ILM

Использован ILM из `25INVITES-ILM1.0.json`, SHA исходного загруженного JSON:
`65ef72c81cd54b665e95cf6954ee080ebb098fee25b2db12773a93a94dd88315`.
Это отличается от раннего `game.modded.ilm.js`.

Сохранены четыре класса, 13 методов с конструкторами, история целей, линии и
цикл 50 мс. AST совпадает после удаления 14 неиспользуемых псевдонимов декодера.
Есть сравнение ядра на 180 сценах по шесть тактов и установленного мода с
оригинальным приёмником/рендером/таймером на 36 × 60 = 2160 состояниях.

Сохранены 14 параметров: AimBotEnabled, AimbotKey, autoFire, target,
mouseFovEnable, mouseFov, lockId, distanceCoefficient, bulletSpeedCoefficient,
resolverType, offsetCoefficient, visualizeResolving, visualizeResolvingColor,
ShowRealAngles. В оригинальном ILM resolverType и bulletSpeedCoefficient не
участвуют в расчёте упреждения; не утверждать обратное и не изобретать алгоритм
ради видимости работы этих настроек.

Без цели исходный цикл передаёт последний угол. При autoFire=false таймер
наведения отправляет только [6, угол]. Ручная атака остаётся штатной. При
autoFire=true повторяется пара [4]/[5] на каждом такте, пока истинно исходное
условие ILM. Нативные обработчики направления продолжают своё bookkeeping,
но не дублируют отправку при включённом аимботе. Краткий разрыв соединения не
стирает историю; сбросом при id=0 управляет исходный цикл ILM.

### AutoBuild

Перенесён из исходного `_0xeb562b`: каждый активный нативный кадр отправляет
`[14, 0, PLAYER.y / 100, PLAYER.x / 100]` через кодек новой игры.
Ноль — поворот постройки, НЕ слот инвентаря. Строится выбранная штатной игрой
постройка под персонажем. Нет старой задержки 120 мс и зависимости от курсорного
предпросмотра. Дробные координаты до кодека не округляются. RAF не дублирует
нативную отправку. Automation → AutoBuild; исходная клавиша B, переназначение
сохраняется. Нужны допустимые игровые условия и материалы; применение сервером
не подменяется клиентским рисунком. Живая постройка с материалами отдельно не
проверялась: подтверждены сравнение исходной логики и нативные входы кодека.

### Остальные изменения

FAutoLoot работает на каждом нативном кадре, как ILM: квадрат расстояния
меньше 41000, фильтр и [12,id]. Не возвращать старые задержки 125/250 мс и
ограничение одним предметом. SAutoLoot — отдельный режим.

ник#ID подключён к нативным начальным метаданным, появлению, подписям над
игроками и таблице лидеров. Пустые неиспользуемые слоты остаются числовым 0.
Цвета своего/чужого клана работают с нативным кэшем и проверкой поколения.

Удалены дополнительные нижние подписи HP/еды/стамины и надпись AIM BOT над
персонажем. Сохранены меню, клавиши, фильтр, масштаб и список активных функций.

### Cookies, токен и повторный вход

Пользователь требует сохранять прежнего персонажа/токен. Не очищать cookies,
localStorage, accountToken и не создавать новую идентичность как способ
починить вход. Настройки мода изолированы в DevastILM:settings:v3 с миграцией
старых настроек. Поля аккаунта не включаются в сохранение настроек мода.

Исправлены воспроизводимые зависания SDK preroll/createAdPlayer, временный busy
при ошибке/таймауте, устаревшие ответы HTTP до изменения ключей и ожидание
подтверждения WebSocket. Есть ограниченный повтор с прежними данными.
Контрольный живой вход с теми же cookies прошёл, но это не гарантия для любого
профиля пользователя. Подробности: REJOIN-FIX.md и датированные отчёты.

## 6. Незавершённый вопрос: внезапная смерть после атаки

Пользователь сообщал «Вы умерли» после атаки с аимботом и уточнил, что autoFire
был выключен. Причина именно этого случая НЕ установлена; не заявлять, что
античит обойдён или отсутствие киков гарантировано.

Проверенный путь аимбота при autoFire=false отправляет [6,угол] раз в 50 мс.
Отдельного сообщения «используется аимбот» в этом пути не найдено. Это не
устанавливает серверные методы обнаружения по поведению.

Нативный бинарный пакет с opcode 5 вызывает удаление собственного персонажа
и переход смерти с флагом 128. В контрольном прогоне пойман `05 00 00`, когда
аимбот был выключен, а HP постепенно снизились почти до нуля. Такой пакет
используется и при обычной смерти; сам по себе он не доказывает античит.
Блокировка сообщения в браузере не восстановит серверного персонажа.

Добавлена диагностика: Connection → «Копировать отчёт входа». После сбоя
пользователь должен скопировать её ДО перезагрузки. В памяти сохраняются
события server-death/socket-close, HP, aim/autoFire, число команд мода за
две секунды, deathOpcode, deathPacketLength, deathPrefixHex. Только первые три
байта проверенного пакета смерти; произвольные ответы, значения токенов и
cookies не экспортируются. Этот отчёт пользователь пока не прислал.

Контроль автоогня 36 секунд прошёл, но использовал искусственную историю цели
и стрельбу в воздух; попадания в другого игрока этим не подтверждены. Отдельные
попытки ручного боя были заблокированы недоступным сервером или смертью до
начала боя. Не выдавать эти попытки за успешное воспроизведение проблемы.

## 7. Полная система автообновления

Основной конфиг: auto-update.json. Локальный watch — каждые 300 секунд.
GitHub Actions — расписание */15, push в main и workflow_dispatch. Наличие
workflow не доказывает успешное выполнение в конкретный момент: смотреть runs.

```sh
npm run build
npm test
npm run update:once
npm run update:status
```

update:once читает актуальный HTML devast.io, находит подходящие /js/*.js,
проверяет хеш, статически декодирует, сопоставляет AST и привязки, переносит
ТЕКУЩИЕ модули мода, выполняет Chromium, тесты переведённого установщика и
полную регрессию. Затем атомарно меняет current.json. При нераспознанной
совместимости должен оставлять прежний проверенный файл.

Полный скачанный игровой JS и старое пользовательское вложение не запускать
в Node для «расшифровки». Не заменять сопоставление простым изменением SHA
или строковых имён наугад. Не отключать проверки ради зелёного статуса.

Для постоянного процесса, просмотра и локального сервера:

```sh
npm run update:watch
npm run update:status
npm run update:serve
```

serve обслуживает localhost:8787, это не публичный хостинг. Watch работает
только пока жив процесс. Откат: `npm run update:rollback`; прежний выпуск должен
быть сохранён локально. В переносной ZIP включён только текущий выпуск, поэтому
локального предыдущего выпуска для отката там может не быть.

### Проверить сохранённый JS без новой загрузки HTML/JS

В архиве есть raw.js и index.html последнего проверенного выпуска. Это позволяет
проверить перенос на закреплённом снимке при временном HTTP 503. Такая проверка
НЕ подтверждает, что на сайте ещё нет более нового JS. Браузеру/зависимостям
всё ещё может требоваться доступ к внешним ресурсам.

```sh
python3 - <<'PY'
from pathlib import Path
import json, shutil
from tools.update_client import pipeline
root = Path.cwd()
current = json.loads((root/'dist/auto-update/current.json').read_text())
saved = root/'dist/auto-update/versions'/current['release']
work = root/'build/saved-snapshot-check'
work.mkdir(parents=True, exist_ok=True)
for name in ['raw.js', 'index.html', 'source.json']:
    shutil.copyfile(saved/name, work/name)
validation = pipeline(root, work, current['source_url'])
print(validation['status'], validation['regression'])
PY
```

Не подменять таким результатом факт успешного свежего скачивания. Изменения
mod/patches/tools/tests во время проверки меняют fingerprint: дождаться конца
проверок перед редактированием этих файлов или запустить проверки заново.

## 8. Публикация после новой разрешённой задачи

Исходники живут в main, проверенный клиент и ZIP — в updates. Для публикации
нужны права GitHub в новой среде. Не force-push; не терять новые коммиты.

1. Завершить изменение в исходниках, сборку, нужные проверки и отчёт.
2. Проверить diff и явно выбрать изменённые файлы; не добавлять .npmrc/секреты.
3. Сделать обычный commit и push HEAD:refs/heads/main при разрешённой публикации.
4. Выполнить `python3 tools/publish_update.py` для проверенного current.json.
   Если проверенная версия лежит в другом каталоге, есть `--output КАТАЛОГ`.
5. Проверить анонимной загрузкой current.json, verification.json и JS, сравнить
   SHA файла с манифестом. При HTTP 503 сообщать, что осталось не опубликовано.

publish_update.py проверяет результаты тестов, хеши модуля/override и файла,
создаёт ZIP и обновляет updates без checkout этой ветки и без принудительной
перезаписи чужих изменений. Публиковать ручной непроверенный JS мимо этой
проверки нельзя как будто он прошёл систему автообновления.

Стабильные ссылки:

- JS: https://raw.githubusercontent.com/Abricos2050934/Devast-io/updates/game.modded.js
- Манифест: https://raw.githubusercontent.com/Abricos2050934/Devast-io/updates/current.json
- Проверки: https://raw.githubusercontent.com/Abricos2050934/Devast-io/updates/verification.json
- JSON: https://raw.githubusercontent.com/Abricos2050934/Devast-io/updates/Devast-io-GitHub-Resource-Override.json
- Клиентский ZIP: https://github.com/Abricos2050934/Devast-io/raw/refs/heads/updates/Devast-io-client.zip?download=1
- ZIP импорта: https://github.com/Abricos2050934/Devast-io/raw/refs/heads/updates/Devast-io-Resource-Override.zip?download=1

Resource Override JSON — синхронный загрузчик с cachebuster к updates/game.modded.js.
Подменяет основной игровой JS ДО его запуска. Полный клиент не исполнять поверх
уже запущенного оригинала. При старом встроенном полном JS замена загрузчика
может требоваться отдельно. Очистка cookies для обновления не требуется.

## 9. Источники истины и старые материалы

Приоритет: новая задача пользователя → актуальный код/тесты и отчёты с
совпадающим SHA → ILM-PORT.md, AUTO-UPDATE.md и эта инструкция. Более старые
