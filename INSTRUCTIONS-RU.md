# Devast-io: продолжение проекта и перенос на другой GitHub

Снимок инструкции: 3 ноября 2026 года. Исходный репозиторий:
https://github.com/Abricos2050934/Devast-io . Это техническая передача состояния,
а не восстановленная дословная переписка ChatGPT. Актуальные хеши, версии и результаты
нужно брать из MANIFEST.json архива и соответствующего validation.json.

## Что скачать и сохранить вне GitHub

1. **Devast-io-Handoff.zip** — главный файл. В нём все текущие исходники, тесты,
   workflows, закреплённая база игры, извлечения ILM, текущий проверенный выпуск,
   готовый клиент и инструкции. Его достаточно для нового чата и нового репозитория.
2. **NEW-CHAT-PROMPT.txt** — готовый текст для вставки в новый чат. Копия есть в ZIP.
3. **Devast-io-main-history.bundle** — необязательная полная история ветки исходников.
   Новому чату обычно не нужно загружать этот большой файл. История ветки updates
   отдельно не включена: её текущий выпуск включён в основной ZIP, а ветка
   восстанавливается инструментом публикации.
4. **SHA256SUMS.txt** рядом с загрузками — контрольные суммы скачанных файлов.

Сохранить файлы на своём ПК и желательно на втором носителе. Ссылка на GitHub
не является независимой резервной копией, если аккаунт станет недоступен.
Архив не требует доступа к старому GitHub для восстановления исходников.
В нём нет .git/config, node_modules, .updater, личных cookies, игрового профиля,
паролей, переменных окружения или учётных данных GitHub. Bundle содержит объекты
Git и коммиты, но не локальную конфигурацию и не механизмы авторизации.

## Что передать новому чату

Прикрепить главный ZIP и вставить handoff/NEW-CHAT-PROMPT.txt. Если нужен переезд,
вписать **NEW_OWNER/NEW_REPOSITORY** и попросить выполнить перенос. Если нужна другая
работа — описать её. Без выбранного нового адреса не придумывать репозиторий.

Новому агенту сначала прочитать эту инструкцию, handoff/CURRENT-STATE.md,
handoff/MIGRATE-TO-NEW-GITHUB.md, MANIFEST.json и применимые инструкции среды.
Проверить git status при наличии checkout; не затирать чужие изменения.
После распаковки главного ZIP перейти в Devast-io-Handoff и выполнить:

```sh
python3 handoff/verify_archive.py
```

Это офлайн-проверка контрольных сумм; игровой код не выполняется.
Архивные контрольные суммы нужно проверить ДО редактирования файлов.
После осознанного изменения ссылок проверка исходного архива ожидаемо покажет
различия; нельзя подгонять старый манифест, выдавая изменения за исходный снимок.

## Состояние проекта

Полный рабочий контекст и ограничения: handoff/CURRENT-STATE.md.
Главные действующие требования пользователя:

- Сохранить Jitter: J по умолчанию, скорость задаётся в меню, вращение стоя и
  при ручном движении; при стрельбе уступает наведению. Не менять native input.angle.
- AutoBuild на B использует допустимую клетку штатного предпросмотра ПОД КУРСОРОМ,
  выбранную постройку и штатный поворот. Не возвращать установку под ногами.
- Оригинальное ядро ILM сохранено дословно. Поверх него работает отключаемый
  Improved prediction с временными метками и скоростью пули из метаданных оружия.
- Сохранить единый canvas штатного кадра и проверки Firefox: пользователь играет
  на ПК в Firefox и неоднократно сообщал о FPS/задержках.
- Сохранить ник#ID, цвета ников/кланов, список игроков, zoom, loot, контейнеры,
  бинды, настройки и последние исправления входа.
- Не очищать cookies/localStorage/token/tokenId/userId. Не заменять личность при входе.
- Сохранить перенос и проверки всех ТРЁХ служебных подписей i_/n_/t_.
  Не вставлять фиксированные старые значения. Неизвестная логика должна блокировать
  обновление. Проверки совместимости не доказывают отсутствие серверных киков.

Не применять заново уже выполненные изменения. Новые указания пользователя имеют
приоритет; сохранённые условия действуют, пока пользователь их явно не изменит.

## Файлы и источники истины

| Путь | Роль |
| --- | --- |
| mod/responsive.js | Настройки, адаптер наведения, AutoBuild, Jitter, GUI, вход, общий canvas |
| mod/ilm-aim.js | Оригинал ILM, исходные меню/линии и отдельное улучшенное упреждение |
| mod/bootstrap.js | Привязка к текущему нативному клиенту, восстановление входа, integrity flag |
| mod/contract.json | Обязательные функции, модули, тесты и оба браузера |
| tools/updater/integrity.cjs | Перенос трёх известных условий в служебных подписях |
| tools/auto_port.cjs | Декодирование/AST-сопоставление нативных контрактов и новая сборка |
| tools/update_client.py | Получение актуального JS, перенос, два браузера, тесты, выбор версии |
| tools/validate_update.cjs | Настоящие нативные обработчики с подготовленными данными |
| tools/publish_update.py | Публикация только проверенного текущего выпуска в updates |
| patches/ | Канонические привязки и проверенные точки вставок |
| baselines/ | Закреплённая официальная база, не редактировать ради прохождения тестов |
| recovery/ | Извлечённые исходные блоки ILM и материалы сравнения |
| resource-override/ | Активный загрузчик и импортируемый JSON |
| tests/ | Проверки мода, переноса, публикации, подписей, входа и интерфейса |
| verification/ | Отчёты с конкретными SHA; старые отчёты — история |
| dist/auto-update/ | В ZIP включён текущий полностью проверенный выпуск и его материалы |
| client/ | Удобные готовые файлы, включая независимый от GitHub офлайн-JSON |
| handoff/ | Контекст, помощник смены ссылок, проверка архива и сборка нового бэкапа |

**dist/game.modded.js — базовая сборка для разработки. Не подменять ею проверенный
клиент из client/ или dist/auto-update.** Автоматический перенос добавляет три
проверенных условия совместимости подписей; публикация должна идти через
update:once и publish_update.py. Старый tools/package_client.py с фиксированными
историческими логами/числом тестов не использовать для текущих выпусков.

Полный 25INVITES-ILM1.0.json не нужен для текущих сборок: необходимые блоки
сохранены в recovery. Внешние license/webhook/startup-части оригинала не включены.
Если будущая задача требует другой, ещё не извлечённой функции ILM, нужен полный
исходный JSON пользователя. Исторический recovery/game.modded.ilm.js.gz — иной
ранний скрипт, не замена позднему оригиналу и не база нового протокола.

## Установка и проверка в новой среде

Нужны Node.js 24, Python 3.12+, Git и браузеры Playwright:

```sh
npm ci --ignore-scripts
npx playwright-core install --with-deps chromium firefox
npm run build
npm test
npm run update:once
```

На Linux установка системных зависимостей браузеров может требовать права
администратора. При системном Chromium путь можно задать CHROMIUM_PATH.
Для особого расположения скачанных браузеров использовать PLAYWRIGHT_BROWSERS_PATH.
Сохранять прокси, CA и штатный механизм авторизации среды; не отключать TLS.
В управляемой облачной среде прочитать её актуальный runtime skill.

При недоступности сети исходники и готовый снимок всё равно восстанавливаются;
скачивание зависимостей и новой игры потребует сети. Нельзя объявлять их запуск
проверенным, если он фактически не прошёл.

Автообновление обязано проверить Chromium И Firefox для одного SHA256, три подписи
в каждом браузере, тесты переведённого установщика и полный npm test. Не публиковать
сборку, где не прошёл любой из этих этапов. При обновлении игры сохраняется весь
текущий мод, а не накладывается старый готовый JS поверх нового клиента.

## Если старый GitHub заблокирован

Подробные команды — handoff/MIGRATE-TO-NEW-GITHUB.md. Кратко:

1. Распаковать и проверить ZIP. История Git необязательна.
2. Создать/подключить новый аккаунт обычным способом и выбрать пустой публичный
   репозиторий. Пароли, PAT и игровые токены через чат не передавать.
3. Выполнить handoff/retarget_repository.py с новым OWNER/REPO. Он меняет не только
   loader.js, но и браузерный перехват URL, тесты и сгенерированный JSON.
4. Проверить сборку и автообновление, отправить исходники в main, опубликовать
   проверенный выпуск в updates, убедиться в успешном GitHub Actions.
5. Один раз импортировать JSON НОВОГО репозитория в Resource Override, отключив
   старое правило. Потом последующие обновления вновь приходят без переимпорта.

Смена GitHub не требует очистки cookies игры. Данные игры остаются в браузере.
Публикация по выбранному новому адресу — отдельная задача пользователя; архив сам
ничего не создаёт, не отправляет и не использует старые учётные данные.

## Готовый клиент без GitHub

client/game.modded.js — точная копия проверенного выпуска.
client/Devast-io-Offline-Resource-Override.json содержит его целиком и не скачивает
JS с GitHub. Импортировать этот JSON, отключить остальные подмены основного JS,
перезагрузить страницу. Это закреплённый снимок для совместимой версии игры,
не вечное автообновление: после изменений протокола может потребоваться пересборка.
Нельзя выполнять полный JS вторым клиентом поверх уже запущенной игры.

## История Git

Главного ZIP достаточно. Если нужна полная история исходников, сохранить bundle
и проверить его SHA256 из MANIFEST.json. Git-конфигурацию/credentials архив не переносит.
Восстановление истории и её объединение со снимком описаны в инструкции миграции.
Историю updates можно начать заново; текущий проверенный выпуск уже есть в ZIP.

# Восстановление без старого GitHub

Главного ZIP достаточно. Новый чат не обязан иметь доступ к старому аккаунту.
До переноса проверить архив и сохранить его исходную копию.

## 1. Распаковка и проверка

Распаковать Devast-io-Handoff.zip. На Windows можно использовать «Извлечь всё»,
а технические команды поручить новому чату в его облачной среде/Linux.
В каталоге Devast-io-Handoff:

```sh
python3 handoff/verify_archive.py
```

При расхождении SHA256 не продолжать публикацию до выяснения причины.
Для восстановления с историей проверить SHA bundle из MANIFEST.json, затем:

```sh
git clone /путь/Devast-io-main-history.bundle Devast-io-restored
cd Devast-io-restored
git branch -M main
```

В bundle есть HEAD и ветка исходников; clone не обращается к старому GitHub.
После клонирования можно перенести из распакованного ZIP MANIFEST.json,
SHA256SUMS.txt, client/ и dist/auto-update/ для офлайн-снимка и его проверки.
Не заменять .git и не копировать .git/config из чужой среды. Исходники ZIP и
bundle должны иметь один source_commit; если версии различаются — сначала сравнить.
Git-история не обязательна: без bundle создать новую историю на шаге 4.

## 2. Выбор нового адреса и авторизация

Нужен новый OWNER/REPO, например NewOwner/Devast-io. Создать пустой ПУБЛИЧНЫЙ
репозиторий без автоматически добавленного README/license/.gitignore. Публичность
нужна для анонимной загрузки JS браузером; не вставлять GitHub PAT в игровой JS.
Войти в новый аккаунт/подключить GitHub к новому чату штатным способом.
Архив не переносит авторизацию. Пароли и PAT не отправлять обычным сообщением.

Если доступен gh с уже подключённым новым аккаунтом, чат может создать репозиторий
через gh repo create NEW_OWNER/NEW_REPO --public. Не создавать случайный адрес,
если пользователь ещё не указал владельца и имя.

## 3. Перепривязка ссылок

```sh
python3 handoff/retarget_repository.py NEW_OWNER/NEW_REPO --dry-run
python3 handoff/retarget_repository.py NEW_OWNER/NEW_REPO
```

Помощник не создаёт репозиторий и не отправляет файлы. Он меняет:

- resource-override/loader.js и генерируемый JSON;
- tools/validate_update.cjs — URL перехвата новой сборки в обоих браузерах;
- tools/check_resource_override.cjs и tests/resource-override.test.cjs;
- текущие ссылки в README, AUTO-UPDATE и инструкции Resource Override.

Операция идемпотентна, результат записан в handoff/MIGRATION-STATE.json.
Не делать глобальный replace в baselines/, recovery/, истории Git и старых
verification/: это испортит исходники и привязку исторических хешей.
Официальный URL игры в auto-update.json не заменять GitHub-адресом.

## 4. Зависимости, Git и проверки

```sh
npm ci --ignore-scripts
npx playwright-core install --with-deps chromium firefox
npm run build
npm test
npm run update:once
```

update:once проверяет и Chromium, и Firefox, а также 3 подписи. Во время него
не менять исходники: защита входных хешей отменит выбор кандидата.
При недоступности игры/неизвестном контракте сохранить диагностику и исправлять
причину; не отключать проверки и не публиковать старый dist как новую сборку.

Если .git отсутствует:

```sh
git init -b main
git add .
git commit -m "Restore Devast-io project from verified backup"
git remote add origin https://github.com/NEW_OWNER/NEW_REPO.git
```

Если Git восстановлен из bundle:

```sh
git branch -M main
git remote set-url origin https://github.com/NEW_OWNER/NEW_REPO.git
git add .
git commit -m "Point client and validation at the new repository"
```

Если remote origin ещё нет — использовать remote add вместо set-url.
При необходимости задать локальные user.name/user.email для Git. Не помещать
учётные данные в remote URL. Не использовать force push поверх чужих данных.
Игнорируемые MANIFEST.json, SHA256SUMS.txt и client/ — резервные копии, не исходники
нового main. Генерируемый dist/auto-update тоже не коммитится в main.

## 5. Публикация и работа автоматики

```sh
git push -u origin main
python3 tools/publish_update.py
```

Publisher сам создаст/обновит updates, сохранив проверки и ZIP. Если готовая
версия не соответствует текущему моду/JSON/контракту/двум браузерам/трём подписям,
он обязан отказать. После смены loader URL нужна новая проверенная сборка,
даже если сам JS мода остался побайтово прежним.

Убедиться, что main — ветка по умолчанию и Actions разрешены. При необходимости
включить workflow, затем запустить и проверить:

```sh
gh workflow enable auto-update.yml --repo NEW_OWNER/NEW_REPO
gh workflow run auto-update.yml --repo NEW_OWNER/NEW_REPO --ref main
gh run list --repo NEW_OWNER/NEW_REPO --workflow auto-update.yml --limit 5
```

Расписание задано каждые 15 минут, но GitHub может задерживать запуск.
Успешный workflow должен завершить также Publish the verified client.
Сверить публичные current.json, verification.json и SHA256 game.modded.js;
в обоих браузерах должны быть status=passed и integrity_compatibility с predicates=3.

Новые ссылки:

- https://raw.githubusercontent.com/NEW_OWNER/NEW_REPO/updates/game.modded.js
- https://raw.githubusercontent.com/NEW_OWNER/NEW_REPO/updates/current.json
- https://raw.githubusercontent.com/NEW_OWNER/NEW_REPO/updates/verification.json
- https://raw.githubusercontent.com/NEW_OWNER/NEW_REPO/updates/Devast-io-GitHub-Resource-Override.json

## 6. Переключение браузера пользователя

Скачать JSON из нового updates, импортировать в Resource Override, отключить
старую подмену, перезагрузить Firefox через Ctrl+Shift+R. При смене репозитория
переимпорт нужен ОДИН раз: старое правило не узнает новый адрес само.
Следующие совместимые обновления нового репозитория загружаются при перезагрузке.
Cookies, token/tokenId/userId и localStorage игры не очищать.

Пока новое хранилище не готово, client/Devast-io-Offline-Resource-Override.json
позволяет использовать закреплённый клиент без GitHub, если версия игры совместима.
Отключить остальные правила подмены. Это не постоянное автообновление.
