# Отдельное автообновление Rust

JSON: `resource-override/Devast-io-Rust-Auto-Update.json`. Он подменяет основной
игровой JS до запуска и синхронно получает актуальный полный Rust/Wasm-клиент:

`https://raw.githubusercontent.com/Abricos2050934/Devast-io/updates/rust/client.js`

Отключить прежнюю подмену, импортировать JSON и перезагрузить страницу. Сама
игра запускается один раз; обновление начинает действовать при новой загрузке
страницы. Повторный импорт после каждого обновления не требуется. Ошибки HTTP,
HTML вместо JS, другой тип клиента и незавершённая установка показываются в
консоли. После ошибки загрузку можно повторить. Запущенный клиент повторно не
устанавливается. Весь Wasm включён в client.js.

GitHub Actions проверяет сайт по расписанию 7,22,37,52 минут каждого часа и
при изменениях main. Сначала существующий обновлятор получает игровой JS,
переносит текущие JS-модули и проверяет их. Затем Rust-обновлятор получает именно
этого проверенного кандидата, адаптирует нативные поля и заменяет собственный
блок модулей Rust/Wasm. Игровая часть берётся из нового кандидата, а оптимизированные
собственные Rust-функции сохраняются; мигратор generated.rs не запускается.

Дополнительный workflow `check-update-channels.yml` делает лёгкую проверку
каждые 5 минут: сравнивает URL и хеш игрового JS, версии обоих опубликованных
каналов и хеш исходников Rust. При расхождении сам вызывает workflow сборки;
если сборка уже идёт, повторно её не запускает. Ничего собирать и публиковать
вручную при обычном изменении игры не требуется. Оба расписания исполняет GitHub,
поэтому точное время запуска зависит от его очереди.

Условия выбора Rust-выпуска: проверки JS, сборка canonical Wasm, его тесты,
проверки моста/движения/кеша, сборка native Wasm, его тесты, Chromium и Firefox
на полном новом клиенте. Проверяются хеши клиента, исходников Rust и исходного
игрового JS. До публикации сайт проверяется ещё раз. Указатель current.json
меняется после проверок. При неизвестном изменении игры или ошибке теста прежний
опубликованный клиент сохраняется. Файлы JS и Rust имеют разные пути, поэтому
публикация одного канала не затирает другой.

Метаданные: `updates/rust/current.json`, доказательства проверок:
`updates/rust/verification.json`, закреплённые клиенты:
`updates/rust/versions/<release>/client.js`. Локальные результаты находятся в
`dist/rust-auto-update/versions/`; публикация выполняется существующим механизмом
git с отдельным индексом и только fast-forward push.

Команды из полного репозитория:

```sh
npm run update:once
npm run update:rust
npm run publish:rust
```

Нужны Node 24, Python 3.12+, Rust с wasm32-unknown-unknown, wasm-bindgen-cli
0.2.105, Chromium и Firefox. При ручном запуске `update:rust` использует уже
проверенный JS-кандидат; предварительно выполнить `update:once`. Старые локальные
автономные JSON и закреплённая база остаются архивными вариантами. Браузерные
fixtures не подтверждают вход на живой сервер, отсутствие киков или стабильный
FPS на любом устройстве. Ранее описанные пики плотных сцен не устранены этим
изменением механизма обновления.
