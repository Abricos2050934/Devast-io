# Проверка автоматического обновления 25 ноября

Монитор `check-update-channels.yml` работает на GitHub и каждые пять минут
сравнивает URL и SHA-256 актуального игрового JS с метаданными обоих каналов.
При расхождении он сам запускает `auto-update.yml`. Этот workflow переносит
модуль на новый игровой JS, проверяет JS-клиент, публикует его, затем собирает,
проверяет и публикует Rust/Wasm-клиент из того же кандидата.

Проверка журналов Actions обнаружила реальный блокер: новый игровой JS
`6XTwmwoCfUf8gAauG.js` изменил вторую ветку интерполятора угла с проверки ID
на проверку типа сущности. Старое структурное сопоставление отклоняло функцию
с ошибкой `ilm-native-self-server-angle`, поэтому монитор запускал сборки,
но публикации не происходило.

В `tools/updater/server-angle.cjs` добавлено узкое сопоставление этой формы.
Проверяется вся оставшаяся функция; новая нативная проверка типа сохраняется
в выходном JS. Изменение других вычислений или неоднозначное совпадение
по-прежнему останавливает перенос. Отдельные тесты проверяют успешный перенос
и отказ при изменившейся интерполяции, неподдерживаемом поле или дубликатах.

JSON Resource Override уже содержит постоянный адрес загрузчика. При каждом
открытии страницы он получает опубликованный `updates/rust/client.js` с
параметром времени против кеша. Повторный импорт JSON после смены игрового JS
не требуется. В уже открытой игре новая версия применяется после перезагрузки.
Сборка занимает дополнительное время после обнаружения изменения. Неизвестные
изменения игры, которые не прошли проверку, автоматически не публикуются.
