# Закрытое автообновление по индивидуальным JSON

Статус: подготовлено для Cloudflare Workers. Развёртывание и переход репозитория
в private ещё не выполнены. Нынешняя публичная ссылка продолжает работать.

Схема: личный JSON → HTTPS Worker с проверкой ключа → проверенная сборка из
закрытой ветки `updates`. GitHub-токен остаётся в секретах Worker, пользователю
передаётся только ключ конкретного JSON. В ответе нет исходников `main`, ссылки
GitHub для обхода авторизации или GitHub-токена.

Это ограничение доступа, а не защита от копирования получателем. Человек,
которому выдан JSON, может переслать его и сохранить работающий JS. Отзыв ключа
останавливает следующие загрузки, но не удаляет ранее сохранённые копии.
Уже скачанные публичные версии и внешние копии репозитория вернуть невозможно.

## 1. Создать Worker

В Cloudflare Dashboard открыть Workers & Pages → Create → Worker, создать
`devast-private-updates`. В редакторе заменить код содержимым `worker.mjs`,
сохранить и развернуть. Сохранить HTTPS-адрес `https://....workers.dev`.
Домен покупать не требуется. Ничего не добавлять в игровую страницу вручную.

Для запуска через CLI предусмотрен `wrangler.toml`:

```sh
npx wrangler@4.157.0 deploy --config private-updates/wrangler.toml
```

В Cloudflare → Worker → Settings → Variables and Secrets установить:

| Имя | Тип | Значение |
| --- | --- | --- |
| GITHUB_REPOSITORY | Text | Abricos2050934/Devast-io |
| GITHUB_TOKEN | Secret | Fine-grained GitHub token: только этот репозиторий, Contents: Read-only |
| ACCESS_KEYS_JSON | Secret | Содержимое локального `.private-updates/licenses.json` после выдачи ключей |

GitHub-токен создать в Settings → Developer settings → Personal access tokens →
Fine-grained tokens. У него должен быть доступ к репозиторию и после перехода в
private. Его вводят непосредственно в Cloudflare; в чат и JSON для игроков
он не передаётся. До настройки Worker отвечает ошибкой и не выдаёт файлы.

## 2. Выдать отдельный JSON каждому человеку

После появления действительного адреса Worker:

```sh
node private-updates/issue-key.cjs issue --endpoint https://YOUR-WORKER.workers.dev --name friend1
node private-updates/issue-key.cjs issue --endpoint https://YOUR-WORKER.workers.dev --name friend2
```

Генератор сообщает только пути файлов, без вывода ключей. Выданные JSON и база
ключей находятся в `.private-updates/`, исключённой из Git. Файлы имеют права 0600.
`licenses.json` содержит хеши ключей; каждый JSON содержит свой ключ загрузки.
Передать человеку только его `Devast-private-NAME.json`, не базу ключей.
Файлы нельзя публиковать в публичном репозитории или GitHub Releases.

После выдачи/отзыва ключей обновить секрет ACCESS_KEYS_JSON через Dashboard или:

```sh
npx wrangler@4.157.0 secret put ACCESS_KEYS_JSON --config private-updates/wrangler.toml < .private-updates/licenses.json
```

Чтобы отозвать конкретный доступ:

```sh
node private-updates/issue-key.cjs revoke --name friend1
```

Затем ещё раз обновить секрет. Для ограничения срока можно добавить соответствующей
записи `expiresAt` с датой ISO, например `2026-12-01T00:00:00Z`.

## 3. Проверить и переключить

1. Проверить, что `/client.js` и `/current.json` без ключа возвращают 401 и не
   выдают клиент. С настроенным ключом `/client.js` должен вернуть рабочий JS.
2. В Resource Override отключить прежние правила Devast.io, импортировать свой
   новый JSON и полностью перезагрузить игру. Проверить запуск и доступ к серверу.
3. Передать новым пользователям их индивидуальные JSON. Старый публичный
   загрузчик после закрытия репозитория работать не будет.
4. Только после проверки заменить видимость репозитория на private. Проверить
   анонимный доступ к репозиторию, raw JS, ZIP, веткам и прежним прямым ссылкам.
   Сервер Worker должен продолжить получать сборки со своим токеном.
5. Оставить включённым текущий GitHub Actions workflow: он собирает и проверяет
   клиент внутри того же репозитория и публикует в его закрытую ветку updates.
   Проверить доступность Actions и лимиты выбранного GitHub-плана.

Нельзя сохранить анонимную публичную raw-ссылку одновременно с запретом на
скачивание по ней. При недоступном Worker загрузчик не обращается к старому
публичному адресу. Не нужно менять настройки аимбота или код игры: выдаётся
тот же проверенный клиент, а SHA256 проверяется перед отдачей.

## Проверки

```sh
node --test tests/private-updates.test.cjs
node private-updates/check-browser.cjs
```

Тесты проверяют анонимные запросы, отзыв, срок действия, CORS, передачу ключа,
фиксацию версии GitHub, хеш файла, отсутствие публичного запасного адреса и
отсутствие GitHub-токена в ответах. Браузерный тест использует настоящую XHR
в Chromium и подменённые ответы сервиса; это не проверка развёрнутого Worker.
