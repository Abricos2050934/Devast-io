# Продолжение расследования после автолута

8 ноября 2026 года, Москва. Проверка продолжена за пределами ранее исправленного FAutoLoot. За эталон взят тот же присланный Untitled-1_mod_v4.js, SHA256 40ad33f240b76b8770c7390bd5fc9c9ad79534c7b1a6585013f513c601ad3155. Сам ILM 1.0 и его исходные формулы не заменялись.

## Дополнительные воспроизведённые ошибки

**Удалённая фиксированная цель.** После направления0° удаление игрока2 сбрасывает Target в(-1,-1). Наша версия продолжала считать его зафиксированной целью, отправляла[6,225] и удерживала управление мышью. На той же последовательности настоящий движок эталона снимает эту цель и сохраняет0°. Подробности — invalid-target-before.json. Допуск транспорта теперь требует активных собственных координат, активной цели и отличия цели от себя. При нарушении не проходит весь автоматический цикл направления/атаки/отпускания; мышь получает управление. Неверная линия не рисуется. Возврат цели снова передаёт исходный угол ILM. Расчёт/история/такты исходного ядра сохраняются даже для недопущенного результата; invalid-target-after.json это показывает. Это исправление клиентской ошибки, не установленная причина конкретного серверного завершения. В старом отчёте пользователя lockId=-1 и другой движок, поэтому опыт с фиксированной целью не реконструирует тот матч.

**Повторы AutoBuild.** В подготовленной сцене с неизменным допустимым предпросмотром за2секунды при153FPS наш мод отправлял306команд14. Настоящий grokAutoBuildTick эталона на его таймере25мс и внутренней паузе30мс отправлял39. Теперь автоматические установки допускаются раз в50мс: тот же опыт даёт39. Между проходами применяется последний нативный предпросмотр/поворот, а пропущенные проходы не воспроизводятся после паузы. Ручная нативная установка не подменялась. Фильтры и очередь FAutoLoot из предыдущего исправления сохранены. Данные — build-rate-before.json/build-rate-after.json.

**Старая история после быстрого входа.** Если onSessionStart/onHandshake происходят раньше очередного50мс-такта, адаптер только переключал dead, но игроки1/2 и гул17 сохраняли active/старые координаты. Без новых позиций следующий такт отправлял[6,0] по старой цели. Новый вход теперь сразу очищает обе группы через исходный setInactive и снимает targetPlayer; дополнительных тактов расчёта не добавлено. Переприсвоенный ID/UID начинает историю с[-1,-1,-1], а до новых координат команд нет. Это соответствует отдельному сбросу состояния между матчами; исходный ILM в штатном id0-такте очищает только игроков, поэтому полагаться только на этот такт было недостаточно. Результаты — session-history-before.json/session-history-after.json. Это воспроизведение гонки в адаптере, не определённая причина20-минутного пользовательского сеанса.

**Пропуск автосообщений в диагностике.** SpamChat вызывает родной метод напрямую, а не __send, поэтому прежние счётчики не учитывали эти отправки. Теперь успешный вызов с результатом0 учитывается как команда1, отказы/ожидание — нет. Текст сообщения не записывается. Это устранённая неполнота отчёта, а не найденная причина кика. Проверяется отдельным сценарием tests/mod-traffic.test.cjs.

## Другие проверенные области

Просмотрены все36разрешённых операций изменения native: камера/отрисовка/метаданные, история пакетов, отправка и возврат управления мыши, вход/переподключение/смерть/таймауты и три операции совместимости подписей. Реестр с контрольными суммами — native-operation-review.json. Набор native-операций не расширялся. Предыдущий полный индекс функций остаётся в verification/traffic-and-kick-2026-11-08/function-indexes.json.gz.

У guardHandshakeCallback проверено владение попыткой входа и отсечение старого ответа до изменения ключа. При подключении generation меняется каждый кадр. Теоретически это может отсечь ответ, пришедший позже начала матча, но не установлено, что такой ответ в реальном протоколе должен приниматься. Защита не удалена без доказательства. В Connection добавлены wrapped/accepted/rejectedStale/rejectedWhileConnected/rejectedAfterDispose, без URL и данных ответа. Сценарий проверки показывает отдельный счётчик отклонения при network.state1 и сохранение прежнего поведения; этот синтетический ответ не объявляется наблюдением реального сервера.

Также проверен загрузчик Resource Override: правило ограничено hostname devast.io, в текущем HTML только один собственный /js/*.js. Webgames SDK с другого домена этим правилом не подменяется; защита повторного запуска есть. Ошибочный прежний широкий Playwright-маршрут не переносится в выводы о реальном JSON пользователя. Неподтверждённая проблема загрузчика не объявлялась причиной.

Две динамические eval-точки дополнительно прослеживались статически; полного нового серверного кода не получено. Пассивное CDP-наблюдение обычного клиента не дошло до готовой страницы из-за сетевого таймаута. Три существующие операции совместимости служебных подписей, родной пакет смерти и сохранённые учётные данные оставлены. Утверждения об отсутствии иных серверных проверок или гарантированном исчезновении киков не делаются.

## Проверки

Независимая сверка по-прежнему сравнивает2400состояний с неизменённым исходным ILM. Отправленные пакеты проверяются строго против оригинальных пакетов после явно заданного допуска валидности, включая недопущенные состояния, а не против слепой отправки недействительных целей. Отдельно проверяются настоящие нативные обработчики мыши при удалении/возврате цели, собственная цель, отсутствие своих координат и целостность4/5 при изменении очереди. Ни формула, ни допуск не подменены в эталоне. Условия допуска в тесте вычисляются по независимому эталонному состоянию.

AutoBuild проверяется на высокой частоте, текущей клетке/повороте, отключении, неверном предпросмотре и восстановлении очереди. В обоих браузерах нужны valid_live_aim_targets и bounded_auto_build; издатель блокирует отсутствующий результат. Новые счётчики проверены на копирование/отсутствие URL и текста сообщений. Полный штатный конвейер пройден: 166 Node + 56 Python, 111 проверок перенесённого клиента, Chromium/Firefox.
