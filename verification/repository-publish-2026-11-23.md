# Проверка снимка перед отправкой в GitHub, 23 ноября 2026

Проверялся коммит со всеми TypeScript-исходниками мода, сгенерированным клиентом,
Resource Override, инструментами переноса, тестами и сохранёнными артефактами.

Выполнены команды:

```sh
npm run typecheck
npm run check:generated
npm run build
npm test
node --test tests/updater-rotation.test.cjs
```

Результаты:

- строгая проверка TypeScript 5.9.3 прошла для пяти исполняемых модулей и общих
  контрактов;
- сгенерированный JavaScript совпал с результатом компиляции TypeScript;
- сборка воспроизвела клиент SHA256
  `0108257047af8675a566eb39060a187798b9a70c26c409fafa507f8c4cf7686c`;
- 87 Python-тестов прошли;
- 380 из 386 Node-тестов прошли в полном прогоне;
- оставшиеся шесть ротационных тестов сначала выявили устаревшее ожидание числа
  обязательных bindings: после добавления проверяемого `nativeHomeEnter` результат
  стал 83, а тест всё ещё ожидал 82;
- ожидание обновлено до 83 и добавлена отдельная проверка наличия
  `nativeHomeEnter` в каждой ротации;
- все шесть исторических ротаций после исправления прошли.

Исполняемый код при исправлении теста не менялся. Сборка не оставила отличий в
`dist/` или сгенерированных модулях. Живой серверный сеанс в этой проверке не
запускался.

## Ротация во время GitHub Actions

Первый автоматический выпуск после push был остановлен сообщением
`Game script list changed during validation; release is stale`: сайт сменил JS,
пока проверялся кандидат. Это ожидаемая защита от публикации устаревшей сборки.

При повторном запуске обнаружен официальный файл
`https://devast.io/js/leZs64ZPgDsXo.js`, SHA256
`9e84275413e96268144d98febd374d72bbcdecce81adfb1be1ee98117ae7992f`.
Автоматический перенос создал клиент SHA256
`4527a6e46d6ed3d89b7a74f13eb4f6c719ed44279a7d986b2e173fb3f0fa0dfd`.

Chromium 157 один раз зарегистрировал `Cannot read properties of null (reading
'appendChild')` после завершения остальных проверок. Fixture всё ещё загружал
асинхронные Exapush и Google Tag Manager из сети. Эти сторонние скрипты заменены
пустыми локальными ответами, как уже делалось с рекламным Widget и аудио. Для
будущей диагностики `pageerror` теперь сохраняет стек, а правило нулевого числа
ошибок страницы сохранено.

После изоляции сторонних скриптов полный кандидат прошёл локальные браузерные
fixtures в Chromium 156 и Firefox 153 без `pageerror`. Это проверка клиента на
подготовленных данных, а не живая серверная сессия.
