# Сравнение старого и нового JS Devast.io

Проверено 5 ноября 2026. Новый файл заново скачан с сайта игры; его SHA256 совпал с проверенной базой. Сравнивается нативный клиент игры, а не наш аимбот поверх него. Дополнительно полностью проиндексирован старый PRP из вложения.

## Главный результат

Найден модуль проверки стека, преобразования объектов и следов вмешательства. Он **уже есть в старом JS**: целая функция совпала по нормализованному AST, включая её строки и константы. Новый отдельный модуль, проверяющий именно неестественную наводку, этим сравнением не установлен. Правила серверной проверки из клиентского JS не восстановлены.

| Размер этой функции, символов | 26133 | 26090 |

Числа маркеров относятся к раскрытым представлениям файлов. Хеш нормализованного AST функции проверки: `33c26a04645a800e7b8a05fb28c4ff04bb0f7ced18cb790754ad49b1ddc87ea4`. Совпадение нормализованной структуры не доказывает равенства каждого внешнего значения при исполнении.

В старом коде общий флаг проверки называется `ո̌︃`, в новом — `ѕ०̊`. В обоих найдены три статических места чтения флага при вычислении служебных подписей. Функции нового файла: `а１๐` (строка 122303), `ⲅࡃ०` (142494), `ܐ̄︁` (149310). Внешняя оболочка проверок `[native code]` отличается обфускацией; считать всю оболочку побитно либо поведенчески идентичной оснований нет.

## Подтверждённые добавления

- Аккаунтный API `https://account.devast.io/v1/`, вход/профиль/ранги/кланы. Модуль начинается со строки 217961 нового раскрытого файла.
- Пакет входа вырос с 11 до 13 полей: добавлены одноразовый билет аккаунта и ID аккаунта. Это не произвольно добавленная телеметрия аимбота.
- Исходящие команды 39 и 40 связаны с интерфейсом турелей: маской целей и кнопкой боезапаса.
- Новый менеджер модальных окон начинается со строки 216344. Найденные 13 дополнительных вызовов `close()` закрывают окна; их нельзя считать 13 новыми сетевыми киками.
- Строки `Kick`, `The devaster was kicked.` относятся к управлению участниками клана; сообщения о бане аккаунта и рейтинге также не доказывают проверку наведения.

В нативном коде число обнаруженных прямых мест `send` изменилось 6 → 7: добавился XHR-помощник аккаунтного API. Конструкторов WebSocket по-прежнему три. Это статические места вызовов, а не измеренная частота пакетов. Идентификация API ограничена разрешаемыми в анализаторе обращениями; это не доказательство отсутствия любых скрытых сетевых путей.

## Полный перечень различий

| Категория сопоставления функций | Количество |
| --- | ---: |
| Определения в старом нативном JS | 15168 |
| Определения в новом нативном JS | 16340 |
| Пары с одинаковым нормализованным AST, без повторного учёта | 8405 |
| Похожие пары по редким смысловым строкам, требуют проверки | 200 |
| Несопоставленные определения нового файла | 7735 |
| Несопоставленные определения старого файла | 6563 |

**Несопоставленное определение не означает новую функцию игры или античит:** на результат влияют перемещения и новая обфускация. 8405 + 200 + 7735 покрывают все определения нового файла; 8405 + 200 + 6563 — все определения старого. Названия, строки и категории каждой функции находятся в [functions.csv](functions.csv). Извлечённые функции проверки: [старая](old-stack-probe.js) и [новая](new-stack-probe.js); это фрагменты для чтения, не устанавливаемые скрипты. Дополнительная таблица старого PRP — [prp-functions.csv](prp-functions.csv).

В строковых литералах: 1689 значений есть только в новом файле, 434 — только в старом; у 365 общих значений изменилось число вхождений. Полные машинные итоги — [summary.json](summary.json). Это значения строк, не число новых игровых возможностей.

В локальном архиве есть весь `complete-source.diff`, обе раскрытые версии, полные индексы AST и дополнительный diff PRP. Проверка применила каждый diff к старому раскрытому файлу и получила новый **байт в байт**. Поэтому текстовые изменения не ограничены вручную выбранными фрагментами. Для чтения строк используются `sources/old-native.full.js` и `sources/new-native.full.js` из архива.

## Предел полноты

В каждом статическом файле остаются два `eval`, зависящие от ответа сервера. При дополнительной попытке получить исторические тела старый token endpoint ответил HTTP 404; его прежние ответы не восстановлены. Поэтому это полное сравнение имеющегося раскрытого текста, **не заявление о полной расшифровке всех исторических серверных шаблонов**. Оригинальные имена переменных из обфускации не возвращены.

Новый код античита для аимбота и связь найденных блоков с конкретным серверным завершением не подтверждены. Удалять по совпадению слова `close` или `kick` было бы удалением в том числе интерфейса игры, а подавление входящей смерти не сохраняет персонажа на сервере.
