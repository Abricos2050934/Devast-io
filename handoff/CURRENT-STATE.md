## Последние реализованные требования

- Пользователь играет в Firefox на ПК. FPS ухудшался; второй полноэкранный canvas
  убран из штатного кадра. Мод рисуется на canvas игры с save/restore и finally.
  Фон игры не очищается модом, исходное состояние контекста восстанавливается.
  В режиме без нативного покадрового hook сохранён отдельный fallback canvas.
- Jitter: J/KeyJ, скорость 1–3600 градусов/с, по умолчанию 360, выключен по умолчанию.
  Стоя или при ручном движении персонаж вращается. Нативное input.angle/движение
  не переписывается. Вращение отправляется одним таймером не чаще 20 Гц,
  при очереди WebSocket пропускается; первый выстрел получает направление цели.
- AutoBuild: B/KeyB; ставит выбранную постройку в допустимую клетку нативного
  предпросмотра под курсором, с его поворотом. Пакет [14, rotation, previewY, previewX].
  Нельзя возвращать [14,0,player.y/100,player.x/100]. Отправка раз на нативный кадр;
  RAF не дублирует её. Недопустимая клетка/нет выбранной постройки — нет отправки.
- ILM: четыре класса, 13 методов с конструкторами и цикл 50 мс сохранены дословно
  после декодирования строк, включая 14 неиспользуемых псевдонимов. Проверяются
  AST и точный текст. Выбор целей, кланы, FOV, lockId и autoFire остаются исходными.
- После просьбы сохранить ILM без доработок пользователь затем ЯВНО разрешил
  улучшить точность. Поэтому есть отдельное расширение Improved prediction,
  включённое по умолчанию. Его выключение возвращает расчёт исходного ILM.
  Временные метки, два согласованных интервала, остановки/развороты, возраст позиции,
  движение стрелка и решение перехвата со скоростью пули текущего оружия.
  Неизвестные метаданные оружия — fallback ILM. Таймер/сетевая частота не меняются.
- Меню Aim Bot сохраняет исходные пять контролов: ShowRealAngles, Target,
  DistanceCoefficient, BulletSpeedCoefficient, OffsetCoefficient; после них
  Improved prediction. Включение аимбота — Space/AimbotKey, меню — H/ModMenuKey.
  В исходном ILM bulletSpeedCoefficient и resolverType не используются формулой;
  в улучшенном режиме bulletSpeedCoefficient масштабирует скорость пули.
- Native weapon table и bullet speed адаптируются при обновлении, а не читаются
  по предположенным старым полям. Это уже ловило ошибку смешения таблиц брони/оружия.
- Сохранены ник#ID, разные цвета ника/своего/чужого клана, список игроков L,
  копирование ников, zoom, loot/filter, AutoTake, Xray и остальные настройки.
- Лишние нижние показатели и надпись AIM BOT над персонажем удалены по запросу.
  Не возвращать их из исходного ILM.
- Ручной огонь без Jitter не добавляет resolve между тактами. Принудительное
  отображение sent-angle при стрельбе удалено по требованию оригинального ILM;
  ShowRealAngles использует штатную интерполяцию серверного угла.

## Вход, cookies и подписи

Сохранены token/tokenId/userId и cookies. Настройки мода вынесены из конфликтующего
старого ключа в DevastILM:settings:v3; чувствительные поля не сохраняются в конфиге.
Повторный Play, зависший SDK и начальная загрузка имеют ограниченное восстановление
с возвратом штатного Play, без сброса личности и без бесконечных попыток.
После настоящей серверной смерти не восстанавливается умершая сессия: нужен Play.

Три служебных значения i_/n_/t_ зависели от общего нативного флага ѕ०̊. В известной
базе владельцы трёх условий — а１๐, ⲅࡃ०, ܐ̄︁. Переносятся изменения только трёх
проверенных предикатов, остальная формула каждой функции сохраняется. Это не
фиксированные числа/подписи, вставляемые из старой сборки.

Механизм tools/updater/integrity.cjs требует совпадения нативных функций по AST,
одного общего var-binding и отсутствия неизвестных чтений флага. Переименование
флага/функций поддерживается. Неизвестный новый алгоритм/чтение — отказ обновления.
В Chromium И Firefox реальный signer запускается с тем же синтетическим входом
при флаге 0 и 1: результаты должны совпасть. Оба отчёта обязаны подтверждать 3
проверки для SHA256 именно этой сборки; иначе publisher откажется публиковать.

Пользователь сообщил, что отдельная сборка не кикает. Внутреннее устройство сервера
не устанавливалось; автоматические проверки не гарантируют отсутствие киков.
Ранний пакет server-death 05 00 02 при health=6 не был доказательством античита.

## Автообновление и доказательства

Workflow активен, расписание */15; на стороне GitHub возможны задержки.
Получает имя JS из HTML, скачивает, статически раскрывает поддерживаемую защиту,
сопоставляет нативные контракты, включает ТЕКУЩИЕ модули, проверяет оба браузера,
кандидатные тесты и npm test. После проверок выбирает версию и публикует updates.
Хеши модулей, полный контракт функций, список тестов, оба браузера и 3 подписи
защищены проверками публикации. При ошибке остаётся предыдущий проверенный выпуск.

Проверен контролируемый совместимый вариант: новое имя JS и девять переименований
(в том числе флаг + все 3 signers); весь перенос и проверки прошли. Вариант с новым
чтением флага отклонён, старый current.json/JS сохранён. Официальные байты игры во
время аудита не изменились: нельзя выдавать эту симуляцию за реальную новую версию.

Симуляция упреждения: 48 сценариев, 25 → 46 пересечений радиуса 38; RMS 60 → 12,3.
Без разброса, препятствий и неизвестной серверной задержки. В двух случаях цель
выходила за путь пули 900. Это не измеренный процент попаданий на живом сервере.
Подготовленный Firefox CPU-замер такта: 0,011 → 0,012 мс, по 9000 команд в обоих
режимах. Другая подготовленная сцена показала снижение CPU рисования с 3 до 1 мс;
FPS обеих Firefox-сцен был около 60. FPS/RTT на ПК пользователя не измерялись.

не спрашивать повторное разрешение на каждый обычный обратимый шаг.
