## Вход, cookies и подписи

Сохранены token/tokenId/userId и cookies. Настройки мода вынесены из конфликтующего
старого ключа в DevastILM:settings:v3; чувствительные поля не сохраняются в конфиге.
Повторный Play, зависший SDK и начальная загрузка имеют ограниченное восстановление
с возвратом штатного Play, без сброса личности и без бесконечных попыток.
После настоящей серверной смерти не восстанавливается умершая сессия: нужен Play.

Три служебных значения i_/n_/t_ зависели от общего нативного флага ѕ०̊. В известной
базе владельцы трёх условий — а１๐, ⲅࡃ०, ܐ̄︁. Переносятся изменения только трёх
проверенных предикатов, остальная формула каждой функции сохраняется. Это не
фиксированные числа/подписи, вставляемые из старой сборки.

Механизм tools/updater/integrity.cjs требует совпадения нативных функций по AST,
одного общего var-binding и отсутствия неизвестных чтений флага. Переименование
флага/функций поддерживается. Неизвестный новый алгоритм/чтение — отказ обновления.
В Chromium И Firefox реальный signer запускается с тем же синтетическим входом
при флаге 0 и 1: результаты должны совпасть. Оба отчёта обязаны подтверждать 3
проверки для SHA256 именно этой сборки; иначе publisher откажется публиковать.

Пользователь сообщил, что отдельная сборка не кикает. Внутреннее устройство сервера
не устанавливалось; автоматические проверки не гарантируют отсутствие киков.
Ранний пакет server-death 05 00 02 при health=6 не был доказательством античита.

## Автообновление и доказательства

Workflow активен, расписание */15; на стороне GitHub возможны задержки.
Получает имя JS из HTML, скачивает, статически раскрывает поддерживаемую защиту,
сопоставляет нативные контракты, включает ТЕКУЩИЕ модули, проверяет оба браузера,
кандидатные тесты и npm test. После проверок выбирает версию и публикует updates.
Хеши модулей, полный контракт функций, список тестов, оба браузера и 3 подписи
защищены проверками публикации. При ошибке остаётся предыдущий проверенный выпуск.

Проверен контролируемый совместимый вариант: новое имя JS и девять переименований
(в том числе флаг + все 3 signers); весь перенос и проверки прошли. Вариант с новым
чтением флага отклонён, старый current.json/JS сохранён. Официальные байты игры во
время аудита не изменились: нельзя выдавать эту симуляцию за реальную новую версию.

Исторические отчёты adaptive-aim и настройки far/close относятся к удалённому
предиктору. Не использовать их как требования к актуальному ILM.

## Для следующего агента

Не откатывать новые функции по устаревшим README/FEATURES/историческим отчётам.
Не редактировать замороженный baseline ради зелёных тестов. Не запускать весь
скачанный JS/старый ILM JSON в Node. Не копировать старые ID облачных сред,
аккаунты/credentials, cookies. Сохранить штатные прокси/CA среды и проверку TLS.

Для нынешнего состояния достаточно ZIP. Полный исходный поздний ILM JSON для
будущего разбора другой функции можно получить у пользователя отдельно.
Новый репозиторий выбирает пользователь. При явно указанной задаче переезда
подготовить, проверить и выполнить её целиком, сохраняя чужие изменения;
не спрашивать повторное разрешение на каждый обычный обратимый шаг.

Сохранено параллельное исправление dba26ff: адаптер текущего нативного транспорта
объединяет повтор одного целочисленного угла, чтобы не подавлять штатный idle-ping.
Расчёт ILM выполняется каждые 50 мс; изменившиеся углы и все attack/release передаются.
Это отличие передачи от старого прямого ws.send учтено отдельно от точного сравнения
состояния, формул, выбора целей, меню и линий оригинала.
