# Автоматическое обновление клиента

Система проверяет сайт локально или в GitHub Actions. Проверенный клиент
публикуется в отдельную ветку updates. Все команды выполняются из
корня репозитория. Нужны Python 3.12+, Node.js 24, зависимости из package-lock.json
и Chromium для обязательной проверки собранного клиента.

В автообновление включены исправления рабочей отдельной сборки: совместимость
трёх нативных служебных подписей и восстановление Play после зависшего входа
(recoveryVersion 5). По сообщению пользователя отдельная версия работает без
киков. Обновлятор переносит эти изменения вместе с текущим аимботом и остальными
функциями; неизвестное изменение нативного контракта блокирует публикацию.

В Connection → «Копировать отчёт входа» автоматическая версия показывает
`auditBuild: integrity-autoupdate-v1` и `integrityCompatibility: true`.
Проверяются все три функции при значениях флага 0/1; публикация требует успешного
результата `integrity_compatibility` в verification.json. Если проверка не прошла,
по постоянной ссылке остаётся предыдущая проверенная версия. Ручная базовая
сборка `npm run build` служит этапом проверки; публикуется результат полного
`npm run update:once`, включающий перенос защищённых нативных функций.

```sh
npm ci --ignore-scripts
npx playwright-core install --with-deps chromium
npm run build
npm run update:once
```

Если установлен системный Chromium, можно задать CHROMIUM_PATH или использовать
автоматически обнаруженный /usr/bin/chromium. В облачной среде сохраняются прокси
и проверка TLS; браузер должен доверять CA среды. Инструкции окружения приведены
в UPDATE.md. Не нужно передавать боту cookies или данные игрового аккаунта.

## Работа бота

```sh
npm run update:watch   # Проверять каждые 300 секунд до остановки процесса
npm run update:status  # Текущая версия и результат последней попытки
npm run update:serve   # Читать готовую сборку через localhost:8787
npm run update:rollback # Вернуться к предыдущей проверенной версии
```

Интервал, разрешённые источники, лимиты и тайм-ауты находятся в auto-update.json.
Постоянный опрос требует работающего процесса watch или планировщика. Подготовлен
workflow .github/workflows/auto-update.yml: на GitHub
он проверяет сайт каждые 15 минут, публикует прошедшую проверки сборку в updates
и сохраняет Actions artifact. Запускается также при изменении main и вручную.
Для публикации нужны права contents:write, заданные в workflow.

## Цепочка обновления

1. Получает текущую HTML-страницу https://devast.io/ и извлекает script src.
   Имя игрового JS не зашито. Сторонние рекламные/аналитические скрипты исключены.
   Разрешены HTTPS, проверенные домены, ограниченное число перенаправлений и размер.
2. Загружает кандидатов /js/*.js, использует ETag/Last-Modified и проверенный кэш.
   Новая версия определяется SHA256 содержимого. Изменение имени или query при
   прежнем содержимом обновляет source_url без повторной сборки. Изменение байтов
   по прежнему URL запускает перенос. Изменение локального мода тоже запускает его.
3. Декодирует таблицу строк и распознаваемые защищённые блоки. Декодер — ограниченный
   интерпретатор допустимых операций со строками/числами/массивами: аргумент eval
   извлекается как текст и разбирается парсером. Полный скачанный клиент в Node
   не запускается. Нераспознаваемые необходимые привязки не угадываются.
4. Сопоставляет функции по нормализованному AST с учётом неизменяемых констант,
   локальных имён, экранирования строк и представления чисел. Переносит необходимые
   привязки текущего мода, проверяет семь сетевых контрактов и все 11 мест вставки. Необходимый
   контракт должен совпасть целиком. Это автоматический перенос совместимой версии,
   а не универсальная замена любого изменённого игрового API.
5. Собирает нативный клиент с текущим модом. Четыре класса и цикл ILM сохраняются
   без изменения алгоритма. Начальная метаинформация после расшифровки патчится
   непосредственно, поэтому ник#ID не зависит от старого имени декодера.
6. Проверяет синтаксис, отсутствие дублированной установки, точное включение мода
   и совпадение ядра ILM. Обязательная проверка в Chromium выполняет настоящие
   обработчики начальных ников, появления, двух подписей, пакетов/удаления и углов.
   Затем проходят функциональные тесты на самом переведённом установщике и
   регрессионные тесты npm test. mod/contract.json задаёт наши модули и функции;
   их хеши записываются в validation.json. Публикация откажется брать сборку другой
   ревизии мода. Нижний текст показателей и надпись AIM BOT удалены из установщика.
7. Записывает всю версию в отдельную папку и только после проверок атомарно меняет
   current.json. До этой точки обслуживается прежняя версия. Одновременные запуски
   блокируются файловой блокировкой; устаревший PID не оставляет вечный lock.

Если есть два различных совместимых JS, выбор считается неоднозначным. При HTTP
403/503, изменившемся необходимом API, ошибке переноса или тестов текущая версия
сохраняется. Отказ записывается в status.json, последний отклонённый кандидат —
в .updater/failed-latest для диагностики. Наличие новой загрузки само по себе не
означает успешное обновление. Последующие циклы продолжают проверять сайт.

## Результаты и будущая ссылка

Локальные артефакты:

- dist/auto-update/current.json — атомарный указатель, SHA256 и source_url;
- dist/auto-update/status.json — состояние последней попытки;
- dist/auto-update/versions/<release>/game.modded.js — неизменяемый готовый клиент;
- рядом лежат raw.js, native.js, profile.json, bindings.json, port-report.json,
  validation.json, журнал переноса и регрессионных тестов.

Сервер npm run update:serve слушает только 127.0.0.1:8787:

- /game.modded.js выдаёт текущую проверенную версию;
- /current.json и /status.json показывают состояние;
- /versions/<release>/game.modded.js выдаёт закреплённую версию.

Доступны ETag, ответы 304 и правильный JavaScript Content-Type. Доступ к другим
файлам репозитория отсутствует. До первой успешной сборки ответ клиента — HTTP 503.
Проверка хеша препятствует выдаче повреждённого файла. Cookies и токены в эти
артефакты не включаются. Постоянный публичный файл: https://raw.githubusercontent.com/Abricos2050934/Devast-io/updates/game.modded.js.
Публикация вручную: python3 tools/publish_update.py. Перед отправкой проверяются
хеш файла, результаты полного набора проверок и соответствие текущим модулям.
В updates попадают JS, ZIP, манифест и отчёт; исходники живут в main.

## Границы проверки

Браузерная проверка использует настоящие обработчики клиента с подготовленными
данными. Она подтверждает правильность известных подключений, но не подтверждает
вход на живой сервер, попадания и отсутствие киков. Переработанный протокол или
новая схема защиты могут потребовать обновления правил переноса; система не
подменяет такой результат старым JS с объявлением «успешно обновлено».

Отчёт о фактическом прогоне: build/auto-update-live/end-to-end.json.


## Импортируемый JSON для Resource Override

Файл resource-override/Devast-io-GitHub-Resource-Override.json сохраняет формат v1
из предоставленного BBY-файла. Он подменяет игровой JS загрузчиком, который получает
наш updates/game.modded.js с GitHub и выполняет его синхронно до продолжения страницы.
Это сохраняет порядок запуска исходного образца. При смене игрового имени JS правило
/js/*.js остаётся действующим; при новой сборке переимпорт JSON не требуется.

Нативная браузерная проверка каждой сборки теперь также запускает кандидата через
этот загрузчик. Хеш JSON записывается в отчёт; публикация откажется подставлять
изменённый непроверенный JSON. JSON автоматически включается в updates и ZIP.
[Импорт и использование](resource-override/README.md).
