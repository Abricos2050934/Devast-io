# Магазин для Devast.io, сервер 67

Сервис принимает штатный вебхук игры `POST /devast` на порту 8000.
Аккаунты, баланс, история денег и незавершённые заказы сохраняются в SQLite.
Python 3.10+; сторонние библиотеки не нужны. Скрипт игры заменять не требуется.

Размещение и установка из GitHub: [HOSTING-ru.md](HOSTING-ru.md).

## Команды игроков

В игровом чате:

```text
login=ВАШ_ЛИЧНЫЙ_ПАРОЛЬ
?bal
?shop
?shop=2
?price=ak47
?buy=ak47
?buy=bullet_9mm*100
?sell=wood*100
?help
```

`login=` — встроенный скрытый логин Devast.io: по официальной инструкции он
не отображается как обычное сообщение чата. Вводи только свой личный пароль
магазина, 8–64 буквы/цифры/символы `_` и `-`, без пробелов. Пароль администратора
сюда вводить не требуется. Не публикуй свой личный пароль обычным сообщением.

Новый пароль создаёт аккаунт с нулевым балансом. Прежний пароль открывает
прежний аккаунт после переподключения, смены ника и перезапуска сервиса.
**Пароль — единственный ключ аккаунта:** опечатка открывает другой, пустой аккаунт;
игроки с одинаковым паролем попадут в один аккаунт. Используй длинный уникальный
пароль и сохрани его у себя. В базе сохраняется медленный солёный scrypt-хеш,
а не исходный пароль. `?bal` также показывает номер аккаунта для администратора.

После первого `login=` дождись приветствия, затем вводи команды. Сообщения
предыдущего логина из 60-секундной истории не выполняются повторно.

Все цены указаны за **один предмет**. Без `*число` покупается одна штука.
За раз можно купить или продать от 1 до 255 штук. Одновременно выполняется
один заказ на аккаунт. Предметы выдаёт именно игровой сервер командой
`!item-to=PID:LOGIN:ITEM*QUANTITY`, продажа использует `!remove-to`.
Ответы магазина приходят персонально через `!message-to` с проверкой текущего
логина, чтобы повторно занятый PID не получил чужую покупку.

Заработок: **10 монет за минуту присутствия в игре**, плюс продажа ресурсов и
других товаров. Два персонажа на одном аккаунте не удваивают награду.
Длительные пропуски вебхуков и время вне игры не оплачиваются.

В `config.json` выставлены цены всех **147 уникальных кодов предметов из
официального списка**. Дубликат `energy_cells` учтён один раз. Список и цены —
`PRICES.csv`. Это покрытие опубликованной таблицы, а не обещание поддержки
неописанных серверных алиасов: новые предметы клиента, которых в официальном
списке нет, перечислены отдельно в `CATALOG-COVERAGE.md`.
Для покупки используются коды из каталога, например `medikit`, а не произвольные
переводы названия. `aliases` связывает код с названием в инвентаре/событии
(например, `steel` → `Iron`, `bullet_9mm` → `Bullet`).

## Локальный запуск и проверка

```bash
python3 -m unittest discover -s tests -v
python3 server.py
```

В Windows с установленным Python можно открыть `start-windows.cmd`.
Проверка процесса: `http://127.0.0.1:8000/health`.
`webhook_connected: false` означает, что процесс работает, но игра ещё не
отправляет события. База по умолчанию — `data/shop.sqlite3`.

Локальный запуск сам по себе **не подключает сервер 67**: Devast.io должен
иметь возможность обратиться к публичному IP хоста на TCP-порту 8000.
Текущая облачная сессия разработки не является постоянным хостингом.

## Подключение на VPS/Linux

1. Скопируй каталог проекта на постоянный хост в `/opt/devast-shop`.
2. Установи Python 3.10+, создай системного пользователя `devast-shop`.
3. Скопируй `deploy/shop.env.example` в `/etc/devast-shop.env`.
4. Укажи `SHOP_HOST=0.0.0.0` и реальные исходящие IP игрового сервера в
   `SHOP_ALLOWED_SOURCES`. Вебхук игры не содержит документированной подписи:
   ограничение по источнику необходимо, чтобы посторонний HTTP-запрос не мог
   подделать подтверждение продажи. Не подставляй IP своего браузера или
   широкую сеть `0.0.0.0/0`. Если перед сервисом прокси, ограничь источники на
   самом прокси/фаерволе; `X-Forwarded-For` приложением не доверяется.
5. Разреши TCP 8000 на фаерволе только от игровых IP. Установи systemd unit:

```bash
sudo cp deploy/devast-shop.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now devast-shop
```

6. Зайди администратором на свой сервер 67 и введи в игровом чате:

```text
!start-webhook=ПУБЛИЧНЫЙ_IP_ХОСТИНГА
```

Используется именно IP хостинга магазина. По официальной инструкции игра
отправляет JSON на `http://IP:8000/devast` примерно раз в 1–2 секунды (два интервала
в руководстве расходятся). При необходимости один раз выполни
`!webhook-world-timeout=5`, чтобы большие снимки мира перестраивались реже.
Магазин не увеличивает частоту снимков мира и не отправляет команды фильтра,
которые могли бы удалить нужные другому сервису поля.

7. Проверь `GET /health` с хоста, дождись `webhook_connected: true`.
   Затем проверь аккаунт, продажу 1 дерева и покупку 1 дерева на тестовом
   персонаже. Подтверждение в базе должно перейти из `sent` в `confirmed`.

Отключение: `!stop-webhook`. После **перезапуска игрового сервера** подписку
нужно включить снова: так работает штатный механизм Devast.io.
Установка поверх уже существующего вебхука может заменить его подписку;
сначала проверь, используется ли он другими службами.

## Подтверждения, потеря соединения и полный инвентарь

Покупка сначала резервирует деньги. Списание выполняется по событию `addItem`
с нужным получателем, названием и фактически выданным количеством.
Продажа сначала отправляет удаление предметов, и лишь событие `remove`
зачисляет деньги. Частичные подтверждения по нескольким стекам суммируются.
Повтор одного события не меняет баланс второй раз, в том числе после рестарта.

Игра не документирует уникальный ID команды и гарантию её однократного
выполнения. Поэтому при потере ответа или отсутствии подтверждения через
90 секунд заказ переходит в `review`. Сервис **не повторяет выдачу автоматически**
и не начисляет деньги только потому, что ресурс исчез из снимка инвентаря:
это мог быть обычный выброс или крафт. Если инвентарь заполнен или игровой
сервер не выдал предмет, заказ также потребует проверки. Это ограничение
протокола, а не доказательство успешной выдачи.

Поле `events[].player` руководство не типизирует однозначно. Настройка
`event_player_reference` по умолчанию `gid`; если реальный первый вебхук
покажет, что сервер использует PID, установи `pid` и перезапусти сервис.
Произвольного угадывания между ID нет. Сообщения/пароли вебхука не логируются.
Сторонняя ручная выдача того же предмета во время незавершённого заказа
может быть неотличима от подтверждения заказа; избегай таких одновременных
операций. Сервис не заявляет недоступную протоколу гарантию exactly-once.

## Локальные команды администратора

Публичного API для накрутки баланса нет. Выполняй команды на хосте магазина
с тем же путём `--db`, с которым запущен сервис:

```bash
python3 manage.py accounts
python3 manage.py credit 1 1000
python3 manage.py orders
python3 manage.py backup backups/shop-backup.sqlite3
```

Для systemd укажи `--db /var/lib/devast-shop/shop.sqlite3`. Резервное копирование
использует SQLite Backup API и включает аккаунты, соль логинов и журнал сделок.
Не копируй отдельно работающий `.sqlite3` без WAL-файла обычной командой `cp`.

Если заказ `review` не был выполнен игрой, после ручной проверки:

```bash
python3 manage.py cancel-order 1
```

Оставшаяся бронь покупки освободится; уже подтверждённая часть останется оплаченной.
Отмена фактически выполненного заказа может подарить предметы бесплатно —
поэтому автоматической отмены нет. Для восстановления утраченного игроком
пароля останови сервис, выполни `python3 manage.py reset-password НОМЕР_АККАУНТА`
(новый пароль вводится скрыто), затем запусти сервис снова.

## Источники и границы проверки

- Официальный протокол и коды товаров: https://devast.io/commands
- Таблица исходных кодов: `manual-items.json`.
- Названия предметов текущего клиента: `item-names-reference.json`.
- Тесты работают с SQLite и настоящим локальным HTTP-сервером. Проверяется
  цепочка логин → продажа → подтверждение → баланс → покупка → подтверждение,
  повтор пакетов, рестарты, частичная выдача, подмена аккаунта и плохие запросы.
- Проект не включает админ-пароль сервера и не подключён к живому серверу 67
  без постоянного публичного хостинга. Первый реальный callback необходим
  для проверки фактических полей событий и выдачи именно на этой версии сервера.
